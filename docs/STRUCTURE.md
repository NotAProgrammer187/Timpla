> Where files go. If a file has no obvious home here, the answer is almost always
> `features/<thing>/` on the frontend or a new controller + policy pair on the backend.

## Monorepo

```
/docs        DESIGN.md · SCREENS.md · STRUCTURE.md · API.md

```

```
    bean/[id].tsx  bean/new.tsx
    recipes.tsx  settings.tsx  stats.tsx
    auth/login.tsx  auth/register.tsx
    welcome.tsx            # first-run
  theme/
    tokens.ts              # THE ONLY FILE ALLOWED TO CONTAIN A HEX CODE

  components/
    ui/                    # the only styled primitives — Button, Chip, Input, Card,
                           # RatingBadge, FreshnessPill, ListRow, BottomSheet, …
    <composite>.tsx        # multi-primitive pieces reused across screens (BrewCard, …)
  features/
    beans/                 # queries.ts · types.ts · freshness.ts
    brews/                 # queries.ts · types.ts · ratio.ts
    recipes/
    profile/

  db/

    client.ts              # expo-sqlite + drizzle instance
    migrations/            # generated by drizzle-kit
    seed.ts                # dev fixtures
  sync/                    # THE ONLY FOLDER THAT MAY TOUCH THE NETWORK
    api.ts                 # typed client for docs/API.md

    auth.ts                # token in expo-secure-store
    photos.ts
  lib/                     # framework-free helpers — uuid, dates, formatting
assets/
  fonts/  images/  illustrations/    # 3D clay art lives here
```

### Rules

1. **`src/app/` routes, the rest of `src/` implements.** A file in `src/app/` should read as layout
   and composition. If it contains a `StyleSheet.create` with more than a handful of lines, or
   business logic, that belongs elsewhere in `src/`. Imports use the `@/` alias, which maps to
   `src/` — `@/theme/tokens`, `@/features/brews/queries`.
2. **`src/theme/tokens.ts` is the only file in the repo containing a hex code.** Everything else
   imports from it. This is enforceable with grep, and it is.
3. **`src/components/ui/` are the only styled primitives.** Screens compose them. A screen that
   needs a new visual pattern gets a new primitive, not a one-off style.
4. **`src/sync/` is the only folder that may import the network client.** Nothing in `features/`,
   `app/`, or `components/` may `fetch`. Delete `src/sync/` and the app must still build and run.
5. **`features/*/queries.ts` is the only place that talks to Drizzle.** Screens call these helpers;
   they never write SQL or import the db client directly.
6. **Lucide icons for functional UI. 3D clay illustrations only for empty / success / error states.**
   Never a clay illustration in nav or a list row.

## `/backend`

```
app/
  Models/            User · Bean · Brew · Recipe
  Policies/          one per synced model — every one checks user_id
  Http/
    Controllers/Api/ AuthController · BeanController · BrewController ·
                     RecipeController · SyncController · PhotoController
    Requests/        one FormRequest per write action
    Resources/       BeanResource · BrewResource · RecipeResource · UserResource
  Services/          SyncService — the merge logic, kept out of the controller
database/
  migrations/        mirror docs/API.md §1 field-for-field
  factories/  seeders/DemoSeeder.php
routes/api.php
tests/Feature/       one file per controller
docker/  Dockerfile  docker-compose.yml
```

### Rules

1. **API-only. No Blade, no web routes, no sessions.** If a view file appears, something went wrong.
2. **Every synced model has a Policy** and every controller calls `authorize()`. Ownership is checked
   on read as well as write — a `403` for someone else's UUID, not a `404`.
3. **Every write endpoint has a FormRequest.** No `$request->all()` reaching a model.
4. **JSON leaves through an API Resource.** Never return a model or an array directly — Resources are
   what keep the wire format identical to `docs/API.md`.
5. **Migrations mirror the Drizzle schema field-for-field.** Timestamps are string columns; see
   `docs/API.md` §1.1 for why.
6. **`SyncService` owns merge logic.** `SyncController` validates, delegates, and formats.

## Naming

| Thing | Convention | Example |
|-------|-----------|---------|
| React components | PascalCase file + export | `RatingBadge.tsx` |
| Route files | expo-router lowercase | `app/brew/[id].tsx` |
| Hooks | `use` prefix | `useFreshness.ts` |
| Query helpers | verb-first | `listBrews`, `upsertBean`, `softDeleteRecipe` |
| Laravel | framework default | `BeanController`, `StoreBeanRequest` |
| Test files | mirror the subject | `tests/Feature/BeanControllerTest.php` |

## Commits

Conventional, scoped by half: `feat(frontend): …` · `fix(backend): …` · `docs: …`.
Branch per feature off `main`, PR into `main`, never commit to `main` directly, never delete a
branch after merge, and never add AI attribution to a commit or PR body.
